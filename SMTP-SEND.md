# Отправка по SMTP — как включить

Gmail подойдёт технически: `smtp.gmail.com:587` + код приложения, и
`send-smtp.ps1` отправит письма сам. Это первый рабочий путь — до этого не было
ни реквизитов, ни клиента, ни релея.

**Но лучше не из личного ящика.** Google банит аккаунты за холодную коммерческую
рассылку, и восстановить его почти невозможно — вместе с почтой и контактами.
Практика: пустой ящик на твоём имени. Мягче к холодным письмам, и потерять
нечего. Идеально — отдельный домен, но это на потом.

## Пароль сюда не присылай

Он попадёт в чат, в логи и в файлы. Скрипт специально сделан так, чтобы этого
не было: пароль вводится в защищённое приглашение и живёт только в памяти
процесса. В NOTES.md, в `.ps1` и в `sent-log.csv` его нет.

## Вариант 1 — вводишь пароль руками (проще)

```powershell
powershell -ExecutionPolicy Bypass -File send-smtp.ps1 -Credential -SmtpHost smtp.yandex.ru -Limit 3
```

Спросит ящик, потом пароль. Вводи в окно, не в чат.

Для Gmail то же самое, но вместо пароля — **код приложения**:

```powershell
powershell -ExecutionPolicy Bypass -File send-smtp.ps1 -Credential -SmtpHost smtp.gmail.com -User твой@gmail.com
```

Код приложения: настройки аккаунта Google → «Безопасность» → «Двухэтапная
аутентификация» → «Пароли приложений». Обычный пароль Gmail по SMTP не работает.

## Вариант 2 — один раз задать переменные

```powershell
setx MAIL_USER "твой@ящик.ru"
setx MAIL_PASS "код-приложения"
# закрыть и открыть окно терминала заново, иначе переменные не подхватятся
powershell -ExecutionPolicy Bypass -File send-smtp.ps1 -UseEnv -Limit 3
```

## Вариант 3 — несколько ящиков (для волны, а не для одного письма)

Один ящик на всю холодную рассылку — это то, за что банят. Несколько пустых
ящиков на одном домене с разделением по дневным лимитам позволяют держать темп
и пережить бан одного ящика, не потеряв остальные.

1. Скопируй `mailboxes.csv.example` в `mailboxes.csv` и правь под себя.
2. На каждую строку задай переменную с **кодом приложения**, не с паролем:

```powershell
setx MAIL_PASS_BOX1 "код-приложения-1"
setx MAIL_PASS_BOX2 "код-приложения-2"
setx MAIL_PASS_BOX3 "код-приложения-3"
```

3. Посмотри план (пароли не нужны, сеть не трогается):

```powershell
powershell -ExecutionPolicy Bypass -File send-smtp.ps1 -Mailboxes mailboxes.csv -DryRun
```

4. Отправка:

```powershell
powershell -ExecutionPolicy Bypass -File send-smtp.ps1 -Mailboxes mailboxes.csv -Limit 10
```

Письма идут по кругу `box1 → box2 → box3 → box1`. У каждого ящика свой
`daily_limit`, и когда он выбран, ящик выпадает из ротации. Если переменная с
паролем не задана, отправка не стартует и называет конкретный ящик — молча
пропускать нельзя, иначе половина пула отключится незаметно.

Проверка логина идёт по **каждому** ящику до отправки первого письма. Непрошедший
выбрасывается из пула, остальные работают. Если не прошёл никто — выход с кодом 4
и ничего не отправлено.

Паролей в `mailboxes.csv` нет и быть не должно: в поле `pass_env` лежит имя
переменной окружения. Файл с паролями в проекте — это компромисс, из которого
потом уезжает доступ ко всему остальному.

## Что делает скрипт

1. Прогоняет `preflight.ps1`. Есть блокеры — не отправляет ничего.
2. Берёт из `eml-index.csv` письма, которые ещё не отправлялись (`sent-log.csv`).
3. Проверяет логин **каждого** ящика пула до отправки первого письма, отбрасывает
   непрошедшие.
4. Шлёт с паузой 45 секунд между письмами. Burst с одного ящика — главная
   причина бана.
5. Пишет `sent-log.csv`: кому, когда, успех или ошибка, **с какого ящика**
   (колонка `from`).
6. В конце печатает разбивку по ящикам.
7. Сдвигает сделку на этап a2 и подсказывает следующий шаг.

`-DryRun` показывает план и не спрашивает пароль. Проверено: 3 письма,
2471-2478 символов текста, 0 плейсхолдеров, 2 вложения в каждом. С пулом
проверено отдельно: 7 писем на 3 ящика раскладываются 3/2/2, ни один лимит не
превышен, `sent-log.csv` после прогона не меняется.

## Порядок

`-Limit 3` в первый день, потом `-Limit 2`, потом по одному. Шесть писем за один
раз технически сработает, но именно «всё сразу» и делает ящик подозрительным.

## Проверка в коде

```powershell
powershell -ExecutionPolicy Bypass -File test-mailbox-pool.ps1   # 33 проверки, без сети
powershell -ExecutionPolicy Bypass -File test-send-wave.ps1      # 18 проверок, без сети
powershell -ExecutionPolicy Bypass -File test-smtp-login.ps1     # сеть, отправки нет
```

`test-smtp-login.ps1` ходит на настоящие `smtp.yandex.ru:587` и
`smtp.gmail.com:465` с заведомо неверными паролями и ждёт отказ 535. Это единственный
способ убедиться, что проверка логина вообще проверяет, а не всегда возвращает
`ok = $true`. Писем не отправляет: сессия заканчивается на `AUTH LOGIN` и `QUIT`.
