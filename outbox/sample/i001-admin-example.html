Автоматизация под эксплуатацию, а не «скрипт и забыл»

Разница между разовым скриптом и системой, которая работает через месяц без меня.

Разовое решение

python parse.py > result.csv

Один раз отработал — и всё. Через неделю упал на новом разделе, кто-то вручную правил таблицу, формат поменялся, и данные перестали приходить. Разбираться некому.

Система

  • Расписание. Запуск по времени, а не по факту «кто-то открыл терминал». Планировщик на сервере, задача не зависит от живого человека.
  • Лог. Дата, источник, число строк, итог. Открыл лог за вчера — сразу видно: было 4200 строк или 0.
  • Уведомление о сбое. Если упало — сообщение приходит сразу, а не обнаруживается через неделю в пустом файле.
  • Частичный успех. Упало на третьем источнике — первые два сохранились, повтор запускается только по третьему.

Состояние в базе, а не в файле

CREATE TABLE runs (
  id        INTEGER PRIMARY KEY,
  started   TEXT,
  finished  TEXT,
  source    TEXT,
  rows_ok   INTEGER,
  status    TEXT,          -- ok | partial | failed
  error     TEXT
);

История прогонов видна сразу: когда последний раз данные были, что упало и почему. Всё это дешевле, чем разбираться по памяти через полгода.

Чего этот пример не делает. Он не разворачивается на вашем сервере. Сервер, домен, SSL и настройка задачи в планировщике — отдельная работа. Сам парсер и логика — то, что показано выше.

Что входит и что нет

  • Входит: скрипт, расписание, лог, уведомление о сбое, база с историей прогонов.
  • Не входит: сервер и домен, настройка доступа к источнику, поддержка сайта, который сломался сам по себе.

Пример работы. Объём и стоимость считаются по вашему источнику и числу прогонов в сутки.
