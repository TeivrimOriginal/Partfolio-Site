Сборщик вакансий hh

hh-page.js — чтение страниц hh без входа: HTTP с чередованием хостов,
разбор HTML по data-qa, разбор RSS-выдачи, разбор карточки выдачи.

Источники измерены 06.10.2026, а не взяты из документации:
- api.hh.ru/vacancies отдаёт 403 и с браузерным, и с «-application»
  User-Agent — официальный API без ключа больше не открыт;
- hh.ru/search/vacancy отдаёт 302;
- zarechny.hh.ru/search/vacancy отдаёт 200 и 1.28 МБ HTML;
- /search/vacancy/rss отдаёт 20 вакансий, 8.8 КБ, на обоих хостах.

Поэтому список кандидатов берётся из RSS: он не зависит от классов
magritte-*, которые hh меняет регулярно. Но в RSS нет полного описания,
а без него нельзя отсечь «требуется высшее образование», поэтому каждый
кандидат дочитывается по карточке.

Сбор в два прохода: RSS даёт кандидатов дёшево, карточка даёт полный текст
для screen(). Проверяются только те, до кого дошла очередь до лимита.

Запуск:
  node hsw-collect.js                 пачка 10, приоритет python
  node hsw-collect.js --batch 20
  node hsw-collect.js --pages 4       страниц выдачи на запрос
  node hsw-collect.js --deep 30       сколько карточек прочитать
  node hsw-collect.js --text "python" один запрос
  node hsw-collect.js --dry-run       без записи в базу

Ошибки, найденные по ходу, все воспроизведены и помечены в коде:

1. qa() брала имя тега из куска между data-qa и «>», то есть сам атрибут, и
   элемент не закрывался: заголовок возвращался длиной 497026 символов —
   вся страница. Проверка «поле не пусто» при этом ПРОХОДИЛА. Имя тега берётся
   по lastIndexOf('<', at). В test-hh-page.js добавлены верхние границы длины,
   и probe-qa-regression.js показывает, что старая версия проваливает 4 поля,
   а новая ни одного.

2. archived определялся по заголовку, а заголовок был полстраницы, поэтому
   «в архиве» находилось где угодно и отсекало живые вакансии.

3. Компания бралась из контейнера vacancy-company, который включает подвал
   блока работодателя. В базу писалось «Aston Финалист Рейтинга работодателей
   hh.ru IT-компания У работодателя есть аккредитация». Точный элемент —
   vacancy-company-name.

4. Пачка наполнялась вакансиями одной компании: выдача отдаёт Aston подряд, и
   из десяти вакансий шесть были Aston. Предел 2 на компанию; лишние пишутся
   в базу с пометкой «вне пачки», потому что вакансия настоящая и держать её
   вне базы нельзя — при следующем сборе она снова попадёт в кандидаты.

5. Бюджет глубокой проверки уменьшался на уже известных вакансиях, хотя похода
   на страницу за ними нет. Пять уже известных съедали пять из двадцати
   проверок, и пачка 10 устойчиво приходила недобранной.

6. Для принятой вакансии screen() не даёт why, а только remote. Печаталось
   verdict.why, и в логе стояло «(python, undefined)».
