# Простая бухгалтерия — конфигурация 1С:Предприятие 8.3

Учебный проект: конфигурация 1С, которая закрывает базовый цикл учёта —
закупка товара, продажа, оплата. Собран в формате дампа конфигурации
(`/DumpConfigToFiles`), то есть это ровно то, что лежит в каталоге конфигурации.

**Что это доказывает:** понимание объектной модели 1С — справочники,
документы с движениями, регистры накопления, регистр сведений, управляемые формы,
модули на встроенном языке BSL, запросы к регистрам, загрузка данных из файлов.

## Состав конфигурации

| Объект | Имя | Назначение |
|---|---|---|
| Справочник | `Контрагенты` | Юрлица и физлица, ИНН/КПП, контакты |
| Справочник | `Номенклатура` | Товары: артикул, штрихкод, ставка НДС, закупочная и продажная цены |
| Справочник | `Склады` | Склады, ответственный |
| Справочник | `БанковскиеСчета` | Подчинён справочнику `Контрагенты` (владелец — контрагент) |
| Перечисление | `ВидыОпераций` | Поступление / Реализация / Оплата / Возврат |
| Документ | `ПоступлениеТоваров` | ТЧ `Товары`: номенклатура, количество, цена, сумма, ставка НДС |
| Документ | `РеализацияТоваров` | То же + контроль отрицательных остатков при проведении |
| Документ | `ПлатежноеПоручение` | Списание денег, закрытие задолженности, управляемая форма |
| Регистр накопления | `ТоварыНаСкладе` | Вид `Остатки`. Измерения: склад, номенклатура. Ресурсы: количество, сумма |
| Регистр накопления | `ВзаиморасчетыСКонтрагентами` | Вид `Остатки`. Долг перед контрагентом и его погашение |
| Регистр накопления | `ДенежныеСредства` | Вид `Остатки`. Остаток по расчётному счёту |
| Регистр сведений | `ЦеныНоменклатуры` | Периодический, независимый. Виды цен: закупочная, продажная |
| Отчёт | — | намеренно нет, см. «Чего нет» |
| Роли | `ПолныеПрава`, `Бухгалтер` | |
| Подсистемы | `Учет` → `Справочники`, `Документы`, `Регистры` | |

## Логика проведения

```
ПоступлениеТоваров      ТоварыНаСкладе = Приход
                        ВзаиморасчетыСКонтрагентами = Приход (долг поставщику)
                        ДенежныеСредства = Приход (если «Оплачен»)

РеализацияТоваров       ТоварыНаСкладе = Расход   (после проверки остатка)
                        ВзаиморасчетыСКонтрагентами = Расход (долг покупателю)
                        ДенежныеСредства = Приход (если «Оплачено покупателем»)

ПлатежноеПоручение      ДенежныеСредства = Расход
                        ВзаиморасчетыСКонтрагентами = Расход
```

Все три документа содержат `ОбработкаУдаленияПроведения` — отмена проведения
очищает движения, а не «откатывает» их вручную.

## Модули BSL

| Модуль | Что делает |
|---|---|
| `CommonModules/ОбщегоНазначения` | Округление, расчёт НДС, работа с массивами и коллекциями, поиск незаполненных полей |
| `CommonModules/БухгалтерскийУчет` | Запросы остатков и оборотов: остаток товара, задолженность контрагента, обороты ДС, поиск отрицательных остатков |
| `CommonModules/ОбменДанными` | Загрузка номенклатуры из CSV, выгрузка в JSON, поиск по артикулу запросом |
| `Documents/*/Ext/ObjectModule.bsl` | Проведение документов, расчёт итогов, проверки |
| `ПлатежноеПоручение/.../Form/Module.bsl` | Клиентский модуль формы: подстановка задолженности, реакция на изменение реквизитов |

## Проверка без платформы

Платформа 1С не нужна, чтобы проверить целостность дампа:

```bash
python tools/validate.py
```

Валидатор проверяет 400+ утверждений: корректность XML, уникальность 90 uuid,
существование всех ссылок `cfg:CatalogRef.*`, соответствие каждого объекта
`Configuration.xml` файлу дампа, полноту `ConfigDumpInfo.xml`, парность
`Процедура/КонецПроцедуры`, `Если/КонецЕсли`, `Цикл/КонецЦикла` в BSL,
использование табов в отступах, а также то, что каждый документ с движениями
реально обращается ко всем объявленным регистрам.

## Как загрузить в конфигуратор

1. Создать пустую информационную базу.
2. `Конфигуратор → Конфигурация → Импорт файла XML` — выбрать `Configuration.xml`
   из корня репозитория.
3. Либо вручную: `Конфигурация → Загрузить конфигурацию из файла`.

Требуется платформа 8.3.12 и выше.

## Чего нет и почему

* **Отчётов на СКД нет.** Схема компоновки данных требует настроек периода,
  которые заполняются формой отчёта; накидывать схему без формы — значит
  отдать нерабочий объект. Это следующий шаг проекта, а не «почти готово».
* **Прав ролей нет.** Роли созданы как объекты метаданных, но набор прав задаётся
  в конфигураторе; генерировать `Rights.xml` вслепую — значит отдать файл,
  который не откроется.
* **Не проверено в самой 1С.** У меня нет платформы 8.3 под рукой, поэтому
  все утверждения о работоспособности — это результат статической проверки
  дампа, а не запуск в конфигураторе. Это единственное, что здесь не доказано.
