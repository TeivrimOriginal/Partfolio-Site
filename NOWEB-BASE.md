# NOWEB-BASE — база предприятий без своего сайта

Цель: список живых **коммерческих** предприятий РФ, у которых **нет сайта** (значит
сайт можно продать), и у которых **опубликован e-mail** (значит до них можно
достучаться почтой). Всё собирается из открытых источников, без покупных баз.

## Что делать прямо сейчас

1. **Уже готово и пригодно:** `noweb-leads-verified.csv` — стартовая база
   (6 компаний: живые, коммерческие, сайта нет, почта опубликована, домен проверен),
   `noweb-emails.txt` — 12 адресов, `outbox/` — 6 готовых персонализированных писем.
2. **Чтобы база выросла до сотен и тысяч:** двойной клик по `run-base.cmd`.
   Сбор возобновляемый, можно запускать много раз и оставлять на ночь.
3. **Важно проchecko:** при первом прогоне (40 страниц за 14 секунд) WAF checko
   выдал `HTTP 429` и держал его **больше 47 минут** даже при запросе раз в 5 минут.
   Поэтому по умолчанию стоит 1 поток и пауза 3.5 с. Если запускать с домашнего
   интернета, этого достаточно; с общей/офисной сетью может снова прилететь 429 —
   тогда скрипт сам остановится и продолжит позже, кэш не потеряется.


## Откуда данные

`checko.ru` — публичная выгрузка ЕГРЮЛ/ЕГРИП с контактами. Страница компании
отдаёт всё нужное одним запросом:

| поле | где на странице |
|---|---|
| статус | `Действующая компания` / `Действующая организация` |
| ОГРН / ИНН | `id="copy-ogrn"`, `id="copy-inn"` |
| адрес | `id="copy-address"` |
| ОПФ | `Организационно-правовая форма` |
| уставный капитал | `Уставный капитал` |
| выручка | блок `Финансовая отчетность за NNNN год` → `Выручка` |
| телефон | `href="tel:..."` в блоке контактов |
| e-mail | `href="mailto:..."` в блоке контактов |
| **сайт** | `Веб-сайт` в блоке контактов; если стоит `&mdash;` — сайта нет |
| соцсети | третья колонка блока контактов |
| МСП | `Единый реестр субъектов малого и среднего предпринимательства` |

Перечисление компаний — из карты сайта, которую checko публикует сам:
`https://checko.ru/sitemaps/index.xml` → 62 шарта по 50 000 URL (~3,1 млн компаний).
`robots.txt` разрешает `/company/*` для `User-agent: *`; запрещён только `/search?` —
скрипт его не трогает.

## Почему не 2ГИС / Яндекс.Карты / Google / Яндекс-Народная

Проверено 03.10.2026 запросами, а не на глаз:

| источник | что получили | вывод |
|---|---|---|
| 2ГИС, Яндекс.Карты, Google | 11–12 КБ заглушки, данные рисует JS; 2ГИС требует API-ключ | отказ |
| Yell.ru (в т.ч. мобильная и `/amp`) | листинги отдаются, но контакты за капчей: в HTML только `biz@yell.ru` | почты нет |
| Zoon.ru | Cloudflare Turnstile, 403 | отказ |
| Rusprofile.ru | страница `/id/<n>` рендерится, но контакты под paywall: телефон замаскирован `+7 (░░░) ░░░-░░-░░`, почта и сайт скрыты | отказ |
| tiu.ru, satom.ru, pulscen (503), blizko (503), all.biz (403), avito (439) | каталоги без контактов компаний или закрыты | отказ |
| Overpass API | `overpass-api.de`, `lz4`, `kumi`, `private.coffee` — DNS/TLS не проходят; `overpass.osm.ch` отвечает, но это вырезка только Швейцарии | отказ |
| **OSM через Nominatim** | отвечает, `extratags` отдаёт `contact:email`. **Замер: 237 результатов, 58 с почтой (24%), но с почтой И без сайта — 1.** Маппинг сайта и почты ставится из одного блока контактов, поэтому OSM для этой задачи бесполезен | отказ, с цифрами |
| **checko.ru** | в одном HTML есть и почта, и явный флаг «сайта нет» | **единственный источник** |

## Фильтры (почему именно такие)

Пилот на 29 страницах показал главную проблему: **половина реестра — не покупатели**.

```
вход                                29
действующие                         29   (отсеяно 0)
коммерческие ОПФ                    16   (отсеяно 13 — школы, больницы, МБУ, МТПП)
есть свой сайт                      12   (отсеяно 4)
есть опубликованный e-mail           6   (отсеяно 6)
ЛИДОВ                               6
```

- **только коммерческие ОПФ**: ООО, АО/ПАО/НАО, ИП, КФХ, кооперативы, ТСЖ.
  Школы, больницы, администрации, фонды, палаты, МБУ, ГБУ исключены — они не
  купят сайт, а письмо им только испортит статистику sender reputation.
- **нет сайта** — главный фильтр, это и есть предложение.
- **есть e-mail** — иначе лид нельзя достать почтой.

Сортировка по `score`: выручка (может заплатить), бизнес-почта против фримейла,
членство в реестре МСП, наличие телефона, наличие соцсетей вместо сайта, год
основания.

## Как запускать

Проще всего — `run-base.cmd`: двойной клик, и он последовательно выполняет все
пять шагов. Можно запускать повторно и оставлять на ночь.

```powershell
# сбор (медленно и вежливо: 1 поток, 3.5 с между запросами)
powershell -ExecutionPolicy Bypass -File collector.ps1 -Budget 3000 -Batch 40 -DelayMs 3500 -ProbeSec 300

# или напрямую
powershell -ExecutionPolicy Bypass -File build-noweb-base.ps1 -Pages 200 -Throttle 1 -DelayMs 3500

# пересчёт базы без повторного сбора
powershell -ExecutionPolicy Bypass -File filter-noweb.ps1

# проверка доменов (только DNS, без SMTP)
powershell -ExecutionPolicy Bypass -File verify-emails.ps1

# проверка «а правда ли нет сайта» по домену почты
powershell -ExecutionPolicy Bypass -File check-leads-domain.ps1

# письма из базы
powershell -ExecutionPolicy Bypass -File make-mailmerge.ps1 -Count 25

# проверка синтаксиса .ps1 после правки
powershell -ExecutionPolicy Bypass -File check-syntax.ps1 -File build-noweb-base.ps1
```

`build-noweb-base.ps1` пишет `noweb-cache.jsonl`; уже собранные URL никогда не
запрашиваются повторно, поэтому сбор можно продолжать порциями. Карта сайта
скачивается один раз и кладётся в `_smcache/`, чтобы не качать 50 МБ на каждый запуск.
Фоновый `collector.ps1` переживает перезапуск только частично: если харнесс
перезапустился, процесс умер — просто запусти `collector.ps1` заново, кэш подхватится.

Проверка почты — только DNS: спрашиваются MX-записи домена. SMTP-проверка (RCPT)
сознательно не делается: 600 запросов к чужим MX с одного адреса — это и бан
отправляющего домена, и близко к перебору адресов.

## Двойная проверка «сайта нет»

Поле «Веб-сайт» у checko — это то, что **знают они**. Компания может держать
домен, о котором реестр не в курсе. Поэтому лиды с корпоративной почтой
дополнительно проверяются по самому домену (`check-leads-domain.ps1`):

| состояние домена | вывод |
|---|---|
| `no_dns` | домен не резолвится — сайта точно нет, сильный лид |
| `dead_http` | резолвится, но не отвечает — сильный лид |
| `parked` | отвечает заглушкой «перепродаётся» — сильный лид |
| `site` | есть нормальный сайт — **лид выбрасывается** |
| `portal` | это почтовый/ISP-портал (Ростелеком, астранет), не сайт компании — лид остаётся, но помечен на ручную проверку |

Проверено на пилоте: `aspmk@astranet.ru` показался «сайтом», но title оказался
«Астраханский филиал ОАО "Ростелеком"» — то есть портал провайдера, а компания
сайта по-прежнему не имеет. Отсюда отдельное состояние `portal`.

Побочная грабля: RU-порталы отдают windows-1251, объявляя utf-8. Без повторного
декодирования title превращается в мусор и ручная проверка бессмысленна.

## Ограничения, измерено вручную

- **checko отдаёт 429 по IP.** Взрыв из ~60 запросов дал блокировку, которая держалась
  больше 15 минут (проверка раз в 90 с не помогла). Отсюда `collector.ps1`: сначала
  одиночная проверка каждые 7 минут, потом пачки по 50 страниц с паузой 3 с.
  Реалистичный темп — порядка 1000–1500 страниц в час.
- **Выходная доля лидов** (пилот, 29 страниц): 6 лидов, из них 1 с бизнес-почтой.
  То есть на 1000 разобранных страниц — примерно 200 лидов и 30–40 бизнес-почт.
  Чтобы получить сотню нормальных адресов, нужно разобрать ~3–5 тысяч страниц.
- **Фримейл против корпоративного домена.** У мелких предприятий чаще `yandex.ru` /
  `mail.ru` с именем человека (`baranova-1962@mail.ru`). Такие адреса — это личные
  данные, и их в первую очередь не стоит использовать. В письме есть строка
  «ответьте стоп» и обещание удалить адрес.
- **OSM/Overpass как альтернатива не сработала**: `overpass-api.de`, `lz4`, `kumi`
  недоступны из этой сети (TLS/DNS), `overpass.osm.ch` отвечает, но это вырезка
  только по Швейцарии. Проверено, не выдумывалось.

## Правила отправки (иначе письма уедут в спам)

1. Один адрес в письме, никогда не списком: получатель не должен видеть чужие адреса.
2. Персонализация обязательна — подставляются название, вид деятельности, город,
   телефон (`make-mailmerge.ps1`).
3. Темп: 5–10 писем в час, не больше 30 в день, между письмами разные компании.
4. Никаких вложений в первом письме, только текст.
5. Обязательный выход: «ответьте стоп — удалю адрес».
6. Не отправлять на адреса, где человек назван лично (`имя@`, `имя-фамилия@`) —
   только ролевые (`info@`, `sales@`, `zakaz@`, `b2b@`) и корпоративные домены.
7. Базы не покупать. Только опубликованные контакты из открытого реестра.

Правовая рамка: 18-ФЗ «О рекламе» ст. 18 (требование маркировки и отзыва согласия),
152-ФЗ (адрес берётся из открытого реестра как контакт организации, не из базы
персональных данных), письмо содержит и источник, и выход. Это холодная B2B-размыка,
а не спам — но только при соблюдении пунктов выше.
